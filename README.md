## 📌 Project Overview

<div align="center">

### *"Institutional-quality financial intelligence, democratized."*

</div>

The **NIFTY100 Financial Intelligence Platform** is a full-stack, production-grade financial analytics system covering all 100 companies of India's premier Nifty 100 index. It bridges the gap between raw public financial data and the high-quality, structured analytics typically reserved for institutional investors.

| | |
|---|---|
| **🎯 What is it?** | A unified platform for financial ratio analysis, AI-powered insights, earnings teardowns, ETL pipelines, stock screening, and portfolio intelligence for Nifty 100 companies. |
| **👥 Who is it for?** | Retail investors, financial analysts, quant researchers, fintech developers, CFA candidates, and data scientists who need institutional-grade Indian market data. |
| **🔥 Problems it solves** | Fragmented data sources, lack of structured ratio databases, absence of free institutional research tools for Indian equities, and the high cost of Bloomberg/Refinitiv terminals. |
| **💡 Why it was built** | To democratize access to financial intelligence for Indian markets — providing the power of institutional research without the enterprise price tag. |

### Key Value Propositions

```
✅ 100+ Nifty companies  →  8 ratio categories  →  50+ computed metrics
✅ Automated ETL         →  Data validation     →  Audit-ready reports
✅ AI-powered insights   →  Interactive charts  →  Export-ready formats
✅ JWT authentication    →  Role-based access   →  Production deployment
```

## 🚀 Installation Guide

### Prerequisites

| Requirement | Minimum Version |
|---|---|
| Python | 3.11+ |
| Node.js | 18+ |
| npm | 9+ |
| PostgreSQL | 14+ (for production) |

### Option A — Local Development

#### 1. Clone the Repository

```bash
git clone https://github.com/MALLAMPOLAIAHGANESH/n100-financial-intelligence-platform.git
cd n100-financial-intelligence-platform
```

#### 2. Backend Setup (FastAPI)

```bash
# Navigate to backend
cd n100

# Create and activate virtual environment
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

# Install Python dependencies
pip install -r requirements.txt

# Copy and configure environment
cp .env.example .env
# Edit .env with your database credentials and secret keys
```

#### 3. Database Setup

```bash
# For development (SQLite — no setup required):
# The app auto-creates the SQLite database on first run.

# For production (PostgreSQL):
psql -U postgres -c "CREATE DATABASE financel_db;"

# Run migrations / seed the database
python run_pipeline.py
```

#### 4. Start the Backend

```bash
# From the n100/ directory with .venv active
uvicorn src.app.main:create_app --factory --host 0.0.0.0 --port 8000 --reload

# API available at:  http://localhost:8000
# Swagger docs at:   http://localhost:8000/docs
# ReDoc at:          http://localhost:8000/redoc
```

#### 5. Frontend Setup (Next.js)

```bash
# Open a new terminal and navigate to frontend
cd frontend

# Install dependencies
npm install

# Copy and configure environment
cp .env.example .env.local
# Set NEXT_PUBLIC_API_URL=http://localhost:8000
```

#### 6. Start the Frontend

```bash
npm run dev

# App available at: http://localhost:3000
```

## 🗄️ Database Schema

<details>
<summary>View full schema</summary>

```sql
-- ── Companies ───────────────────────────────────────────────
CREATE TABLE companies (
    id          SERIAL PRIMARY KEY,
    ticker      VARCHAR(20) UNIQUE NOT NULL,
    name        VARCHAR(200) NOT NULL,
    sector      VARCHAR(100),
    industry    VARCHAR(100),
    market_cap  NUMERIC(20, 2),
    created_at  TIMESTAMP DEFAULT NOW()
);

-- ── Financial Statements ────────────────────────────────────
CREATE TABLE financial_statements (
    id              SERIAL PRIMARY KEY,
    company_id      INTEGER REFERENCES companies(id),
    period          VARCHAR(20),           -- e.g. 'Q4FY24'
    statement_type  VARCHAR(20),           -- 'P&L' | 'BS' | 'CF'
    line_item       VARCHAR(200),
    value           NUMERIC(20, 2),
    currency        VARCHAR(5) DEFAULT 'INR',
    created_at      TIMESTAMP DEFAULT NOW()
);

-- ── Financial Ratios ────────────────────────────────────────
CREATE TABLE financial_ratios (
    id          SERIAL PRIMARY KEY,
    company_id  INTEGER REFERENCES companies(id),
    period      VARCHAR(20),
    ratio_name  VARCHAR(100),
    value       NUMERIC(20, 6),
    category    VARCHAR(50),              -- Profitability | Leverage | etc.
    created_at  TIMESTAMP DEFAULT NOW()
);

-- ── Users ───────────────────────────────────────────────────
CREATE TABLE users (
    id              SERIAL PRIMARY KEY,
    email           VARCHAR(255) UNIQUE NOT NULL,
    hashed_password VARCHAR(255) NOT NULL,
    role            VARCHAR(20) DEFAULT 'viewer', -- admin | analyst | viewer
    is_active       BOOLEAN DEFAULT TRUE,
    created_at      TIMESTAMP DEFAULT NOW()
);

-- ── Portfolio ───────────────────────────────────────────────
CREATE TABLE portfolio (
    id          SERIAL PRIMARY KEY,
    user_id     INTEGER REFERENCES users(id),
    company_id  INTEGER REFERENCES companies(id),
    quantity    NUMERIC(15, 4),
    avg_price   NUMERIC(15, 4),
    created_at  TIMESTAMP DEFAULT NOW()
);

-- ── Watchlist ───────────────────────────────────────────────
CREATE TABLE watchlist (
    id          SERIAL PRIMARY KEY,
    user_id     INTEGER REFERENCES users(id),
    company_id  INTEGER REFERENCES companies(id),
    added_at    TIMESTAMP DEFAULT NOW()
);

-- ── Reports ─────────────────────────────────────────────────
CREATE TABLE reports (
    id          SERIAL PRIMARY KEY,
    user_id     INTEGER REFERENCES users(id),
    title       VARCHAR(255),
    report_type VARCHAR(50),              -- 'earnings' | 'ratio' | 'audit'
    file_path   TEXT,
    created_at  TIMESTAMP DEFAULT NOW()
);
```

## 📐 Financial Ratio Engine

<div align="center">

| Category | Ratios Computed | Key Metrics |
|---|---|---|
| 📈 **Profitability** | 10 | ROE, ROCE, Net/Gross/Operating Margin, EBITDA Margin, Asset Returns |
| 🌱 **Growth** | 8 | Revenue Growth YoY/QoQ, PAT Growth, EPS CAGR, Operating Leverage |
| 💧 **Liquidity** | 6 | Current Ratio, Quick Ratio, Cash Ratio, Working Capital, Cash Conversion |
| ⚖️ **Leverage** | 7 | Debt/Equity, Debt/EBITDA, Interest Coverage, Net Debt/Equity, Gearing |
| ⚙️ **Efficiency** | 6 | Asset Turnover, Inventory Turnover, Receivables Days, Payables Days, Capital Intensity |
| 💰 **Cash Flow** | 6 | FCF Yield, OCF/Net Income, CFO Margin, FCF/EBITDA, Capex Intensity |
| 💎 **Valuation** | 8 | P/E, P/B, EV/EBITDA, EV/Sales, P/FCF, PEG Ratio, Dividend Yield |
| ⚠️ **Risk** | 5 | Beta, Altman Z-Score, Piotroski F-Score, Beneish M-Score, Earnings Quality |

</div>

```
 │  EXTRACTION  │ →  │ VALIDATION  │ →  │   CLEANING  │
 │  NSE/BSE     │    │ Schema Check│    │ Dedup/Null  │
 │  Public Data │    │ Type Assert │    │ Outlier Flag│
 └─────────────┘    └─────────────┘    └──────┬──────┘
                                              │
 ┌─────────────┐    ┌─────────────┐    ┌──────▼──────┐
 │    AUDIT    │ ←  │   LOADING   │ ←  │TRANSFORMATION│
 │ DQ Reports  │    │ PostgreSQL  │    │ Ratio Calc  │
 │ Error Logs  │    │ SQLite Dev  │    │ Normalization│
 └─────────────┘    └─────────────┘    └─────────────┘
```

## ☁️ Deployment

### Render (Recommended)

The repository includes a `render.yaml` Blueprint that provisions the service automatically:

```yaml
services:
  - type: web
    name: financel-web
    env: docker
    plan: free
    dockerfilePath: Dockerfile
    healthCheckPath: /health
    autoDeploy: true
```

**Steps:**
1. Fork this repository
2. Go to [render.com](https://render.com) → **New** → **Blueprint**
3. Connect your GitHub account and select this repo
4. Render auto-detects `render.yaml` and deploys

### Docker (Self-Hosted)

```bash
docker build -t financel-platform .
docker run -p 8000:8000 -e SECRET_KEY=your_secret financel-platform
```

### Vercel (Frontend Only)

```bash
cd frontend
```
